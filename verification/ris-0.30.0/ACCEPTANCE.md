## 시스템과 아키텍처 판단

개인 연구자가 Codex 또는 Claude Code의 주 세션에 목적과 결정권을 제공한다. Coordinator가 프로젝트 제약·이전 결과·작업 의존성을 읽고 다음 연구를 선택한다. Researcher가 근거와 질문, Engineer가 모델·검산·실행, Planner가 후보·의존성·검증 계획, Auditor가 분리된 범위 재구성, Designer가 목적별 표현을 맡는다. 기존 다섯 전문 역할과 주 세션을 유지하고 필요한 역할만 배정하는 구조를 이번 후보에 적용했다.

실행·저장 경계를 코드로 보강했다. 정상 CLI에서 `simulate --record-result`는 검토된 모델을 격리 실행하고 선택된 출력·단위·조건과 소스 해시를 해당 질문의 지식 제안으로 연결한다. 소유자의 실제 반환이 검토된 주장·범위·한계를 포함해야 통합이 가능하다. `findings`의 수신·통합·전달 영수증, 프로젝트 내부 조회, 직접 수정 검토와 `coordinate`의 CAS 선점은 결정론적 helper가 소유한다. 사용자에게 보낼 내용의 중요성, 인과관계 및 독립성 판단은 연구자와 Auditor의 책임이다. 등록된 이름이나 텍스트 비교만으로 과학적 인수를 승인할 수 없다.

A0–A9 후보군 모두를 같은 fixture·입력 조건·기계적 품질 기준으로 비교했다. 청결/누락 및 고정/조건부 전달을 교차한 40개 경로에서 최종 기계적 기준은 동일했다. 누락을 한 구조에만 주입한 최초 실험은 진단 이력으로 보존했다. 이 실험으로 알 수 있는 것은 입력한 의무의 전송·검출 비용이다. 연구 성과나 모델 토큰 기준 Pareto 우위는 UNKNOWN이다. 새 Agent·저장 엔진·독립 Runtime의 이득을 입증할 자료가 없어 기존 역할과 helper 조합을 가역적인 구현 기준으로 선택했다. 전문 Steward, Mentor 등은 실제 비교 전까지 열려 있다. 신규 프로젝트 기본 저장은 `significant`이며 보존할 가치가 있는 발견과 상태만 대상으로 한다. 기존 프로젝트는 `manual` 또는 `milestones`를 유지한다. 변경은 별도 사용자 결정과 설정 hash를 요구한다. 제한 저장·비저장 요청은 세션에 우선 적용한다. 일반 사용자의 직접 편집에서는 협력적 파일 잠금과 preimage·검토가 동작한다. 외부 편집기가 비교 직후 파일을 바꾸는 경쟁 상태는 남아 있다. 무결성 해시는 외부 신뢰 기관의 서명이 아니다.

Q05/Q05-1에 따라 이전 명시적 외부 Study/전략 재사용 계약을 개정했다. `--source-project`는 원 경로를 열기 전에 거절한다. 역사적 외부 참조는 유지하고 활성 검색·전달에서 격리한다. CLI의 명명된 요청 파일·수치 정의는 선택 프로젝트에 준비하거나 지원된 stdin으로 전달한다. 추적 불가능한 자유 형식 복사본과 상속된 대화는 호스트의 입력 격리·신뢰된 출처 관리가 필요하다. 검증한 Linux 작업자는 모델용 인증과 다른 프로젝트를 볼 수 없었다. 인증된 두 호스트의 모든 도구·파일 읽기·네이티브 하위 역할까지 그러한 보호가 적용된다는 근거는 없다. ## 자원과 실행 결정

- 최초 포함사용 조회에서 주간 사용률 0%를 관측했다. 다음 조회에서 ordinaryUsageAllowed=true와 유료 크레딧 잔액 존재를 확인했다. 금액과 인증정보는 보고서에 기록하지 않았다. 사용자가 이번 개발 회귀·최소 E2E 합계 최대 4세션, 캐시 포함 1,000만 토큰 목표, 주간 94% 사전 중단, 포함 사용 전용을 확정했다.
- 실제 제품 평가 모델 세션 0/4, 평가 모델 턴 0, 해당 평가 토큰 0. 개발 보조는 지정된 gpt-6.1-sol/low 설정으로 4개 작업자를 사용했고 동시 4개 이내였다. 모델 및 effort는 생성 도구에 전달한 설정이며 실제 제공자 서비스 로그는 열람하지 않았다. 메인·개발 작업자의 모든 모델 호출 횟수, 캐시 포함 청구 토큰과 금전 비용은 UNKNOWN이다. 별도 비용을 0원으로 산정하지 않았다.
- 사용자 추가 응답은 자원 상한 선택 1건이다. 기술적 마일스톤별 승인은 요청하지 않았다. Host는 원자료 산술, 오류 주입, 입력·역할 대역, 일부 흐름 연결과 테스트 판독을 수행했다. 이를 제품 자율성으로 계상하지 않았다. 개발 경과시간은 [실행 시각](run-times.json), 하위 테스트 시간은 [최종 로그](final-source-tests.log)에 기록했다.
- 유지보수 부담은 추가 helper·동일 규칙의 양 호스트 역할 대응·Linux 격리 의존, 기존 프로젝트 전환과 파일/증거 검토에 있다. 신규 전역 서비스 운영·모델의 실제 대기시간·토큰 절감 효과는 측정하지 않았다.
