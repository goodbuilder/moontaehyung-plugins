# Research exploration and milestone recording

1. Read project context and existing evidence; summarize what is known, inferred and still needed.
2. Ask about desired results/success criteria only where materially unresolved. Research direction,
   acceptable tradeoffs and confirmed choices remain user decisions.
3. Survey primary sources, including recent work and necessary foundational work. Browse for current
   trends. Record actual date window, queries/source channels, retrieval date, inclusion limits,
   source identity/locator and whether abstract, full text, code or results were inspected.
4. Group approaches by mechanism/problem addressed. Compare recent changes, representative evidence,
   limitations and open questions. Separate publication observations from claims of field-wide trends;
   limited access/search failure never proves an empty research gap. Check preprint/published versions.
5. Link trend findings to outcome elements and a breadth inventory of distinct mechanisms: current
   baselines, established and emerging approaches, relevant hybrids and resource-constrained routes.
   Search for missing alternatives and counter-evidence before narrowing; no fixed option cap.
6. Invoke Project Plan's recursive expansion protocol on every viable family. Investigate successive
   data, method, integration, evaluation and fallback choices where relevant. Forecast unselected
   options conditionally; do not wait for user selection to explore their consequences. A comparable
   report or one experiment proposal does not complete this work. Keep deeper questions differentiated
   by the parent choice instead of giving every branch the same generic "collect data and test" leaf.
7. Record breadth coverage, examined/excluded families, evidence limitations, and per-option frontier
   reasons with continuation actions. Stop only at genuine evidence/intent/constraint boundaries or
   a route specified through consequential downstream choices. Prioritize remaining work explicitly.
8. Project Plan owns decomposition, forecasts and graph records. RIS owns source notes and project
   context. Reuse canonical artifacts and stable IDs instead of creating competing reports.

## Recording events
- Goal: record the user's confirmed desired outcome, success criteria and constraints.
- Decision: record explicit selection, reason, authority, conditions and review trigger; preserve the
  previous event and supersession link. Presenting alternatives is not a selection event.
- Verification: record methods, conditions, version, observations, limitations and relevant forecasts.
  An agent can establish a measured result without claiming that the user accepted the choice.
- Save provisional forecasts as part of an authorized plan/map artifact; label them provisional.
  This does not authorize logging all exploratory dialogue or collecting private history.
- Update INDEX/CONTEXT links and active plan at these milestones; record current node and next action.
  Resume from the current source bytes, not an old HTML file. A graph revision is not a new research
  project and does not change project_id or plan_id.

## Candidate overlap is valid

When assembling research candidates, reuse the same decision/option reference in every applicable
candidate. Do not assign a method, dataset, sensor or validation choice to only one candidate, or
remove it from another candidate after it has been used once. Project Plan owns candidate bundles
and candidate-local single/multiple selection rules. Compare commonalities as well as differences;
record each candidate independently and preserve its identity when selections change. A hypothetical
candidate is not a confirmed user decision. Keep the full bundles in the canonical plan for resume.
