# Adaptive research for one project

The main RIS session owns the research objective-to-answer path. At intake preserve the
owner's words, intended deliverable, HARD constraints and permissions. Label new goals
as proposed and inferred preferences as inferred. Present a change to a higher goal
with its alternatives, costs and evidence; retain the existing goal until the owner decides.
The user chooses the priority among quality, time and cost where it changes the result.

## Research loop

1. Select the current question or related stable plan node. Retrieve only the relevant
   local records. Compare an initial recommendation with the best competing explanation,
   its decisive premise and something in the available evidence that could disprove it.
2. Assign actual inspection or computation for a decision-changing question. Follow
   references to primary material. Record the observed extent of the data and the material
   limits of the measurement method. A catalogue description may have a different scope.
3. Under significant recording, the discoverer submits the important claim, conditions,
   independent status dimensions, uncertainty and inspected locators as soon as the result
   is available. Use existing Study observations/tests for managed studies; use findings for
   otherwise unowned consequential claims. Reference the stable owner elsewhere. Preserve
   originating contributors (user, RIS, joint, external observation) and distinguish a
   user-approved choice from a claim. Merge only after checking identity under the same
   conditions. For conditional variants, failure, counterexample or competing mechanisms
   create a separate linked finding with its own evidence. A causal link needs a mechanism,
   rivals and a discriminating check.
4. At each handoff reconcile the actual owner return with the canonical result and its
   limitations. The receiving role checks applicability before using it. Keep unresolved
   or failed checks visible, then select the next task from dependencies and available
   resources. When a bounded project run already has task and resource records, use
   [coordinate](coordination.md) to read the ready work and claim it against the current
   revision before dispatch. Keep unresolved external effects held. Apply internal recovery immediately when new evidence invalidates a premise.
   Use the existing recovery node and its real request count for external deepening.
5. For consequential results, follow blind scope reconstruction. Freeze question-specific
   obligations before revealing producer results to the Auditor. Require separate dispositions
   for each material part of a compound criterion. An unsatisfied obligation routes to its
   source owner. Check the corrected revision against the frozen scope and the outgoing answer.
   A clean comparison also needs positive evidence. Never record a role-name assertion as
   proof of infrastructure isolation. When an independent role is unavailable, report HOLD
   or NOT_RUN and deliver the permitted partial result.
6. Deliver the requested view. Distinguish sufficient, conditional, no feasible option found,
   blocked, waiting for a decision and budget exhausted. Include the evidence needed for the
   user to decide, any limits that could reverse the result and the exact next evidence or
   authorization needed on a blocked branch. Keep unselected branches resumable.

## Ownership and views

Keep the original source, Study, plan or finding authoritative for its own facts. CONTEXT
and INDEX identify the active roots. The question-scoped ledger owns a finding's current
interpretation, provenance and receipts. Strategy has a project-local origin note. The
global learning profile is a separate, explicit host facility. Link citations, question,
concept, option and decision IDs and input revisions across their relevant owners.

Use the [read-only CLI views](views.md) and existing Research Map and plan navigation when requested. A Knowledge view follows
conditioned relationships; an Evidence view follows source revisions and validation; a
Decision view follows criteria and alternatives. A Learning view starts with the requested
concept and prerequisites. A Strategy view follows failed action, discriminating check,
changed action, applicability and result. For a short answer the same relationships can
inform one paragraph. Generate further maps only where they serve the requested deliverable.
On direct edits, inspect the user's text before regeneration. Invalidate affected claims,
decisions, receipts and views; preserve unaffected records and earlier decisions as history.
