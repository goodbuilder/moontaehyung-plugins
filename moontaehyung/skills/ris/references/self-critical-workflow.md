# Unified self-critical research workflow

This reference owns the research control loop. Research exploration owns its complete 12 breadth
checks and return checklist; role workflow owns assignments; Project Plan owns the canonical graph.
Use existing findings, studies, plans and authorized conversation records, not a second ledger.
CLI recovery is specified in [recovery operations](recovery-operations.md). Independent blind
assurance belongs to the research-audit skill; self-criticism cannot substitute for it.

## Select perspectives, investigate, revise

Start from the user's outcome, actual evidence and active unresolved questions. Select perspectives
that could change the answer, include their prerequisites and explain deferred perspectives. There
is no fixed sequence or fixed number of applicable perspectives. The following E01–E12 inventory
is open: add a named perspective when a discovery exposes an omission, and recheck comparable
branches. Labels are stable references, not a completeness score or a closed taxonomy.

| ID | Perspective and question |
| --- | --- |
| E01 | Solution: which interventions, alternatives, complements and practical methods can reach the outcome? |
| E02 | Phenomenon and Causality: which rival causes, interactions or hidden states explain observations? |
| E03 | Objective and Value: are the actual outcome, priorities and user judgments represented? |
| E04 | System Structure: which components, interfaces, dependencies and boundaries shape behavior? |
| E05 | Variable and Sensitivity: which variables, units, bounds and interactions can reverse the result? |
| E06 | Resource: which available or addable resources and shared budgets enable each route? |
| E07 | Constraint and Limit: which stated constraints or evidenced limits exclude or condition a route? |
| E08 | Assumption and Premise: what must be true, what do candidates share, and what negates it? |
| E09 | Failure and Risk: which observed or prospective failure paths and recovery conditions matter? |
| E10 | Analogy and Transfer: what carries from adjacent domains, under which matched conditions? |
| E11 | Evidence and Uncertainty: what was inspected, what contradicts the claim, and how independent is support? |
| E12 | Composition and Emergence: what combinations, interfaces or collective effects change standalone judgments? |

Additional perspectives may include dynamics/time, scale, observability, data patterns, mathematical
representation, counterfactuals, history, inverse aims and boundary choice. Select or invent them
when the evidence warrants it; they need no permanent skill or mandatory new artifact. Process,
coverage, user understanding and dependency checks apply across the selected perspectives.

For each selected perspective record its concrete question, inspected evidence/locator and scope,
assessment, contrary or normal-negative evidence, critical follow-up, action actually performed,
result and affected stable IDs. Mark missing evidence explicitly. A heading, query count, reassuring
self-rating or proposed action does not establish coverage. A normal negative means an expected
failure signature was tested and absent under stated conditions; it does not prove universal safety.
Keep the applicable nonselected perspectives and reason visible in the existing record or answer.

At intake separate user-confirmed purpose, target, hard constraints and permissions from inferred
questions. Select the next action by which plausible result would change which consequential choice.
Compare uncertainty, information value, available methods, safety, cost and earlier strategy outcomes
qualitatively unless measurements support more precision. Assign ready questions to roles by dependency. Work
bottom-up: open the original passage/log, compare a rival prediction, vary and recompute a decisive
assumption, inspect a dependency, or perform an authorized check now. Feed the result back into the
originating question and any newly exposed question. A top-down checklist is an omission detector;
it cannot replace these investigations. Preserve the breadth protocol before ranking.

## Carry the evidence through to the decision

Start with the decision the user will make from the answer. Identify what would have to be
observed to justify it. Trace how the supplied evidence was produced, selected and transformed.
Compare the scope actually observed with the scope the source advertises and the decision
requires. Where those differ, use the original material to check the difference or state what
remains unidentified. When two explanations or options fit the headline result but imply
different action, execute an available check that could separate them. Reuse a relevant earlier
check at its recorded revision.

When a decision-bearing finding will be shortened or passed to another role for delivery,
its evidence owner writes a short, publication-ready passage in the user's language at
verification time. Include the result and the observed scope or source qualification that
governs its use, with its practical consequence. If two facts came from different evidence,
keep their attribution clear. Select the passage from the finding before drafting the summary.
Use the existing authorized note, or keep the passage in memory under manual recording.

At integration collect the marked passages from the roles that checked the underlying evidence.
For each proposed conclusion, compare its supporting role return with the passages selected
for delivery. Carry forward any observation boundary needed to reproduce it and any source
limitation needed to interpret it. If the role already supplied the fact, use that wording or
have the owner review a shorter equivalent. A Coordinator's later selection from a summary
can lose material content upstream of the transport check.

Use the [delivery helper](delivery-operations.md) to render these passages from
their reviewed revisions. Use the rendered text in the final answer. If integrating it into a
larger memo, check the actual outgoing draft against that revision, repair any missing passage,
and deliver the checked wording. A link to the finding cannot convey a qualification the reader
never sees. Keep the selection concise enough for the requested format. If the underlying evidence
or wording changes materially, obtain the required owner correction and re-audit. The helper checks
text transport; the evidence owner and Auditor still assess what belongs in the passage and what
the evidence supports.

## Detect internal failure using observations

Watch the research process while doing the work. The following are indicators to investigate,
not diagnoses inferred merely from their names. For each triggered indicator cite a concrete
observed example and locator, competing explanation, discriminating action, its result and correction.
Also record checked normal negatives; do not invent a failure to fill a checklist.

| Indicator | Concrete observation to look for | Discriminating action and normal negative |
| --- | --- | --- |
| Premature closure | A final recommendation leaves a decision-changing ready question unexamined. | Inspect that branch's source or run its available check; if it is already settled at the applicable revision, record that negative. |
| Confirmation or familiar-family lock | Contrary findings are omitted or every candidate shares an untested premise. | Counter-search and test the negated premise or rival family; a documented contradictory result already incorporated is negative evidence for the indicator. |
| Speculative depth | Child questions, graphs or experiments are listed without inspected evidence or executed analysis. | Perform the highest-value child investigation; existing reproducible results tied to each claimed investigated child are a normal negative. |
| Evidence laundering | Snippets become full reads, derivative sources become independent confirmations, or observations lose conditions. | Open the primary passage and trace provenance; matched scope and independently established provenance are normal negatives. |
| Constraint or identity drift | A candidate, measurement, user selection or requirement is silently substituted. | Compare IDs, conditions and authoritative decision locators; exact applicable matches are normal negatives. |
| Repetition without learning | The same searches recur without a changed premise, result or decision. | Inspect prior query/result lineage and choose a different discriminating channel or method; genuinely changed input is a normal negative. |
| Delegation or assurance illusion | An assignment, unattributed PASS or host intervention is presented as completed independent work. | Inspect actual return, revision and host actions; a verified separate return covering the delivered revision is a normal negative. |
| Transfer failure | A previously successful strategy is applied where its assumptions fail. | Test applicability and a negative control before reuse; bounded agreement only within matched conditions is a normal negative. |

Distinguish a legitimate unknown or authority limit from a strategy failure. Link each observed
deficiency to affected nodes, its supporting evidence, recovery method, expected distinguishing
result and closure or reopening condition. When a structural omission or repeated failure makes
targeted investigation insufficient, start the node's exhaustive sweep immediately, including before
any user feedback. A conflict with the framing may instead require enhanced meta diagnosis.
Add indicators discovered from the run. A structural failure reopens its affected class of questions,
not only the example that exposed it. Correction includes what should have been done initially and
an observed check of the repair. Do not change user goals or permissions to remove a failure.

## Deepening and meta diagnosis

Resolve the stable question against the current project and read its authorized recovery ledger.
For a new question create the node, and on delivery record its result locator. At each subsequent
intake classify the user act against that delivered revision, apply it once with its logical request
ID, and carry out the returned action before closing. Use [the recovery CLI](recovery-operations.md)
when recording is authorized. With manual recording and no such authority, use the active conversation,
state the boundary on later-session recall and continue useful work. Recover unknown prior history
from authorized references; retain observed requests and any warranted earlier fallback.
Keep this operational history to identifiers, scoped references and outcomes.
Track qualifying requests to deepen the same stable question/node using authorized conversation or
existing records. A request qualifies when the user asks for further investigation of that node;
status questions, formatting requests, duplicated delivery and node renaming do not count. Preserve
identity through rewording and record uncertain identity instead of inventing a count. Ordinary
research still investigates consequential ready work before any escalation threshold.

On the third qualifying deepening request, apply an exhaustive sweep **in that same turn**. Do not
merely propose or schedule it. Review every registered perspective, including ones you expect to exclude. Look for relevant
perspectives outside the registry. For each record its question and disposition (investigated,
reused, inapplicable with a specific reason, blocked with a reopening condition, or unperformed).
For investigation link the actual action, evidence and finding; for reuse identify the original
result and check its conditions and revision. Track critical children through actual follow-up.
Any unperformed or blocked required work leaves the sweep partial. Review the full breadth/return checklist,
prior exclusions and assumptions, rival causes, combinations, dependencies and remaining frontier;
perform available decision-relevant investigations even when expensive in effort. Authorization,
actual cost limits and safety constraints remain binding. State what was executed and what remains
at a concrete boundary. Exhaustive means exhaustive within the stated outcome and accessible scope,
not every imaginable combination or a fabricated claim of universal coverage.

After a completed exhaustive sweep, a further qualifying request or continuing observed insufficiency
requires enhanced meta diagnosis. This is not automatic after every sweep. Reconstruct the sequence
from actual queries, inspected evidence, decisions and returns. Compare rival process explanations
(framework blind spot, poor search vocabulary/channel, unsupported exclusion, identity loss, shallow
source inspection, weak discrimination, integration failure or wrong stop rule). For each plausible
explanation identify observed support, contrary evidence and a check that separates it from rivals;
run available checks, change the implicated method, then reinvestigate the affected substantive
question and compare outcomes. Reporting that more diligence is needed is not a diagnosis or repair.

## Lineage, sufficiency and bounded stops

Use stable question, claim, option, candidate, decision, source and revision IDs in existing records.
Represent logical links explicitly: supports/refutes, assumes, depends-on, combines-with and
supersedes/invalidates. Mark AND prerequisites versus OR alternatives, unresolved edges and shared
nodes. A visual tree can show these existing links; do not create a mandatory new database or claim
that rendering proves the logic. On changed evidence trace downstream dependencies, invalidate only
affected claims/recommendations/gates/audits, preserve applicable independent work, then recheck
before restoring validity. Preserve previous evidence and user decisions as attributed history.

Distinguish procedural closure (an assigned action returned or checklist was completed) from evidence
sufficiency (the scoped conclusion is supported under its conditions). Track both. A closed task can
leave research insufficient; enough evidence for a bounded answer need not resolve every frontier.
Give a separate scoped outcome (SUFFICIENT, CONDITIONAL, BLOCKED, WAITING_USER, BUDGET_EXHAUSTED
or NO_FEASIBLE_FOUND as applicable) with the evidence or reopening condition. Preserve existing
run, task, decision and gate statuses separately. Stop when the requested scope is supported or a specific evidence, intent, permission, resource or
agreed budget boundary prevents the next consequential action. Give its effect, next action and
reopening condition. Low-value repetition may be deferred with its unchanged decision value; it is
not automatically BLOCKED. Keep UNKNOWN, HOLD, WAITING_USER, NOT_RUN and resource exhaustion distinct.
Continue independent ready work. No promise of future work substitutes for available investigation.

## Conditional strategy memory

Within authorized recording scope, retain a strategy lesson in existing findings/study/plan history
only with its originating question and evidence IDs, context and conditions, method actually used,
observed outcome, failure/contrary cases, confidence limits and reopening trigger. Separate the
observation from the causal claim that the strategy produced it. Preserve unsuccessful strategies.

Before transfer, map source conditions to the new question, identify mismatches and competing
explanations, then run a small applicable check plus a negative control where the strategy should
not help or its assumptions fail. Record results and whether the lesson transfers, is conditional,
or is rejected. A negative control is an actually inspected comparison or authorized check, not a
hypothetical assurance. If unavailable, keep transfer unverified and bound reliance. Reuse neither
an old conclusion nor a strategy as a universal rule; changed evidence reopens its dependents.

### Store, retrieve and apply a lesson operationally

Use an existing authorized finding, study or plan note. Add the fields below there; do not create a
parallel strategy database or turn a lesson into an unconditional instruction. Use the existing
RIS guarded `update` operation when editing a managed note, preserving its identity and preimage.
Link the note in the existing INDEX/CONTEXT only within the authorized recording scope.

```text
Strategy ID and originating question/node:
Input/source revisions and inspected evidence locators:
Observed failed action and result:
Recovery action actually run and result:
Conditional lesson, competing explanation and confidence limits:
Applicable conditions; mismatches and known failure cases:
Reopening/invalidation trigger:
Transfer target question and input revision:
Retrieved originating note and exact lesson section:
Applicability check and predicted change to next action:
Next action actually run; observed result and evidence locator:
Negative-control action actually run; observed result and interpretation:
Transfer verdict: supported within conditions / conditional / rejected / unverified
```

At a fresh question, first read its current context and linked prior lessons; search only the
selected project's authorized research notes if an applicable lesson is not linked. Keep project-specific strategies within this same project. Quarantine historical external references and start a fresh isolated host context on a project switch. Read the
originating evidence before relying on it. Record what the next action would have been without the
lesson, how retrieval changes it, and the actually executed action and result. A copied lesson,
post-hoc narrative or one successful answer cannot establish changed behavior or causal benefit.
Keep independent test results and transcript locators so a reviewer can check this distinction.
No applicable lesson is a valid result; do not force one onto an unrelated task. If no recording is
authorized, perform the same reasoning in the conversation without saving a new record.
