# Implementation-choice guidance — 0.5.2

## Scope

The shared minimum-sufficient-change policy defines when and how to compare material
implementation approaches before fixing the plan. Create/modify GUI workflows own GUI
choices; design-boundaries owns structural choices. Maintenance and verification reuse
those decisions, expose assumptions, and return only affected choices when needed.

The packaged shared policy is the authoring source. Five identical reference copies keep
personal skills self-contained. Personal/package workflow-specific differences, invocation
metadata, Qt Designer conditions, and existing authorization boundaries are preserved.
No new skills, runtime scripts, mandatory research, interviews, or approval gates are added.

## Limits

These are targeted instruction-following examples, not guarantees for every request or model.
No full GUI, ingestion service, hardware workflow, or dependency integration was implemented
or runtime-tested. The invalidated-assumption case used changed requirements and a checked-in
capability declaration, not a live distributed-storage experiment. Large existing-GUI migration
and every failure combination were not separately exercised.

No comparative token/time benchmark was collected, so no savings claim is made. Plugin
installation/activation is not established by this packaged-source update. Existing system
skills and the Workstation application remain outside this change.
