# RIS 멀티에이전트 완료 검사

Claude 구현 · Codex 독립 검수 인계서

## 현황과 목표

공유 RIS 원본에는 필요한 전문 역할에 기본 위임하는 규칙, Planner의 정본 관리 책임, 산출물 변경 후 재검증 규칙이 반영되어 있다. Engineer와 Designer를 포함한 역할 템플릿이 있으며, 기존 RIS·Project Plan 테스트 44개가 통과했다. 공용 완료 판정기와 두 클라이언트의 훅 연결은 구현 전이다. 확인한 설치 버전은 Codex CLI 0.171.0과 Claude Code 2.1.329다.

목표는 양쪽 클라이언트에서 필수 역할의 실제 호출, 배정한 과제에 대한 결과 반환, 납품 버전 검증이 확인된 경우에만 RIS가 `COMPLETE`를 기록하도록 하는 것이다.

## Claude 구현 범위

1. **파일럿 자동 적용.** 원문 조사, 연구지도 갱신, 브라우저 검증, 독립 감사를 포함하는 `research-map` 범위를 첫 파일럿으로 고정한다. 프로젝트 설정 `role_gate_profile: "research-map"`이 있는 프로젝트에서 기존 방식으로 RIS를 호출하면 사용자 입력 훅이 필수 과제를 등록한다. 활성 연구의 후속 턴은 같은 실행을 이어간다. 사용자가 첫 줄에 `RIS-SIMPLE`을 지정한 턴에는 검사를 적용하지 않는다. 예외 턴은 기존 연구의 미결 상태를 유지한다.
2. **공유 판정기.** 기존 `.ris/state.json`에는 과제와 상태를 두고, `.ris/role-gate/<run_id>.json`에는 실행의 클라이언트·세션·에이전트 ID, 배정 토큰, 입력·산출물 해시와 판정을 둔다. 배정 시 과제 ID, 일회성 토큰, 입력 해시를 발급한다. 결과는 `RIS_RESULT`에 실행 ID, 과제 ID, 토큰, 입력 해시, 상태, 산출물과 근거를 담아 반환한다. 실제 호출·반환 이벤트와 결과를 대조하며, 도착 순서와 역할명만으로 과제를 연결하지 않는다. 저장은 실행 메타데이터로 제한한다. 기존 프로젝트 잠금과 변경 전 해시 확인을 재사용하고, 실행 기록은 원자적으로 교체한다. 파일럿에서는 프로젝트당 활성 상위 세션 하나를 사용한다.
3. **클라이언트 연결.** Codex에서는 `spawn_agent` 도구 결과와 서브에이전트 시작·종료 이벤트를 대조한다. Claude Code에서는 `Agent` 도구 결과와 서브에이전트 이벤트를 대조하고, `SubagentHandback`을 사용한 경우 그 경로에서 전달한 보고서를 읽는다. 각각 파일럿의 `.codex/hooks.json`, `.claude/settings.local.json`으로 설정한다. Codex의 훅 신뢰 절차를 따른다.
4. **종료와 재검증.** 양쪽 `Stop` 훅과 기존 `state update`의 완료 전이가 동일한 판정기를 사용한다. 수행 가능한 누락이면 과제 ID와 다음 행동을 반환해 작업을 계속한다. 같은 누락이 진전 없이 반복되면 자동 계속 요청을 멈추고 미완료로 남긴다. 권한이나 훅 제한으로 실행 증거를 확보하지 못하면 사유를 기록하고 완료 전이를 거부한다. 정본이 바뀌면 새 버전에서 HTML을 생성한다. 검증한 HTML이 바뀌면 브라우저 검증과 해당 화면 감사가 만료된다. 입력과 결과 버전이 그대로인 과제는 재사용할 수 있다.

| 역할 | 인계 증거 |
|---|---|
| Researcher | 질문별 발견, 원문 위치, 반대 근거 또는 확인 한계 |
| Planner | 갱신한 정본 Markdown, 영향받은 분기 ID, Project Plan 검사 결과 |
| Designer | 저장된 정본에서 생성한 HTML, 정본과 HTML 해시 |
| Engineer | 전달할 HTML의 Firefox 검사 결과와 HTML 해시 |
| Auditor | 같은 정본·HTML의 독립 검토 범위, 영향받은 ID, 차단 지적과 판정 |

공유 동작은 이 저장소의 RIS 원본에서 구현하고 클라이언트별 등록은 분리한다. 작업 전 상위 `AGENTS.md`와 기존 변경을 확인한다. 설치 캐시는 배포본으로 취급한다.

## Codex 독립 검수와 합격 기준

| 검수 항목 | 합격 조건 |
|---|---|
| 기본 작동 | 파일럿의 일반 RIS 호출로 필수 과제가 등록된다. Coordinator의 수동 목록 작성에 의존하지 않는다. |
| 호출 누락 | Researcher 없이 종료하려 하면 `Stop`이 빠진 과제를 지목하고 `COMPLETE` 전이가 거부된다. |
| 결과 누락·오연결 | 호출만 했거나 다른 과제의 결과가 돌아오면 미완료다. 중복·역순 이벤트와 이전 실행의 반환은 현재 과제를 통과시키지 않는다. |
| 정상 완료 | 다섯 역할의 호출과 반환을 과제별로 확인하고, 납품 버전과 검증·감사 증거가 일치하며, 차단 지적이 해결되면 `COMPLETE`로 전환된다. |
| 버전 변경 | 검증 후 HTML을 수정하면 현재 버전의 완료 판정이 무효다. 재검증을 거친 변경본만 통과한다. |
| 예외와 실행 불가 | `RIS-SIMPLE`과 파일럿 설정이 없는 프로젝트에서 자동 배정과 종료 차단이 발생하지 않는다. 호출 증거를 확보할 수 없는 파일럿 실행은 사유와 누락 범위를 남기고 미검증으로 유지된다. |

기존 테스트 44개와 새 판정 테스트를 먼저 실행한다. 이어서 격리된 두 클라이언트에서 각각 **미호출 거부, 호출 후 결과 누락 거부, 정상 인계 후 통과**를 실제 재현한다. 합성 테스트와 실제 클라이언트 결과를 구분한다. 한쪽 실제 실행을 확인하지 못하면 해당 클라이언트는 미검증으로 남긴다.

지도 검증은 하위 질문 한 곳과 미결 점선 한 곳이 빠진 소형 사례를 사용한다. Planner가 정본을 수정하고 Designer가 해당 버전에서 HTML을 생성한다. Engineer는 Firefox에서 하위 연결, 기본 펼침, 미결 점선을 확인한다. Auditor는 같은 조건의 분기 전체에서 동일 유형의 누락을 확인한다.

Claude는 변경 파일, 실행 명령, 클라이언트 버전, 과제별 호출 증거, 판정, 정본·HTML 해시와 미수행 항목을 남긴다. Codex는 해당 버전의 변경과 실행 증거를 독립적으로 대조한다. 두 클라이언트가 같은 누락을 거부하고 정상 인계를 통과시켜야 운영 검증이 완료된다. 되돌릴 때는 파일럿 설정과 추가한 훅을 해제하고 연구 기록과 실행 이력을 보존한다.
