## 시험에서 발견하고 바로잡은 차이

- 초기 비교의 구형 로그 ACQ-793은 장비·부하·revision·p95만 담고 있었다. 이를 양성 근거로 사용할 경우 후보 A와의 연결이 빠진다. 최초 자료를 보존하고 A를 명시한 ACQ-795를 두 판본에 동일하게 추가했다. 중간 수정본이 ACQ-793을 A에 귀속하고 별도 현장 ACQ-794까지 인용한 응답을 남겼다. 후속 문구는 실제 후보 귀속이 확인될 때만 권고에 사용하도록 한다. 양성, 귀속 누락, p50 전용을 각각 다시 판정했다.
- 사용자 선택을 기록한 기존판 인계에 요청 범위 밖의 미생성 시각화가 미완료처럼 들어갔다. 실제 요청에 속하는 산출물만 인계하며 요청된 파생물에 한해서 누락을 보고하도록 보완했다.
- 중간판이 지연시간 한도를 추가 최적화 기준처럼 사용할 여지가 있었다. 별도 보관 복원 사례에서 한도가 4일이고 더 빠른 쪽에 추가 가치가 없을 때 3.8일과 2.1일 모두 적격인지 확인했다. 한 논문의 독립 표본 E1·E2와 E1 표의 재게시도 구분했다.
- 방법 비교 응답을 독립 검토한 결과, 중간판의 시험은 방법 간 성능 차이를 찾을 수 있어도 변화의 원인을 식별할 공통 기준이 약했다. 비교 기준을 공유하거나 관련 성분을 직접 관측해야 한다는 구분을 역할 인계에 추가했다.
- 최초 장비 자료에는 장비 revision과 문서 revision의 구분이 불명확했다. 의뢰자의 동일 조건 확인을 다음 턴에서 두 판본 모두에 제공했다. 불충분한 초기 관측과 이후 확인된 조건을 구분해서 채점했다.

## 정정과 재개

두 판본 모두 별도 유효성 확인서를 공개한 뒤 B의 18ms를 근거로 권고했다. 같은 측정의 r2 정정값은 24ms여서 B 권고를 철회했다. A의 15ms는 시뮬레이션뿐이므로 이 시점에서는 입증된 적격안이 없었다. 이전 대화를 전달하지 않은 새 세션은 계획·CONTEXT·HANDOFF에서 판단을 복원했다. 같은 r2를 반복 전달한 전후에 각 판본의 임시 프로젝트 파일 **20개가 전부 바이트 단위로 같았다**. 이후 공개한 A 장비 로그의 p95 17ms로 A를 권고했고, 과거 B 권고와 독립 D-52는 보존했다. 사용자가 최종 선택한 것으로 기록하지 않았다.

원자료는 `control/sequence/{old,new}/{start,qualified,fix,repeat,last}/`에 있다. `review/project-diffs.json`은 변경 파일, 단계별 정본·인계 해시와 독립 항목 보존을 기록한다. 임시 프로젝트의 추천 전용·수치 조회 대조군도 원본과 최종 파일 목록·내용이 같고, 선택을 명시한 프로젝트에는 실제 기록 변경이 있다. 해시 비교는 검사 시점 사이에 쓰고 되돌린 행위까지 배제하지는 못한다.

## 독립 검토와 기술적 한계

- 요청 분기·원자료 계보·탐색 폭의 X/Y 비교에서는 두 판본 모두 단일 수치, 넓은 탐색, 재인용을 포함한 핵심 판단을 수행했다. 1차 판정자가 행정용 지침·디렉터리 탐색과 사용자 자료 읽기를 분리하기 어렵다고 표시한 단일 조회는, 정확한 경로로 재시험했다. `records/final-narrow.md`는 유일한 연구 자료인 표와 역할 설정 파일을 따로 기록한다. 편집 원본 경로와 과거 무조건 7단계의 존재·제거 여부는 독립 소스 감사에서 별도로 대조했다.
- 과학적 판정 비교에서 원래 T4 응답 중 기존판의 공통 기준 사용이 더 명확했다. 보완 후 `records/deliver-testplan.md`에는 기준 구현·A·B를 여러 묶음 크기에서 비교하고 절편·기울기가 각각 달라지는 경우와 유보 경로를 제시했다. 제안한 실험 자체를 수행한 것은 아니다.
- 요청별 귀속을 검토한 기존판 감사에서는 범위 밖의 시각화 미생성 기록을 결함으로 판정했다. 후속 독립 감사는 추천·선택·사실 조회의 적절한 분리를 인정하면서, T8 원로그에 장비 revision이 없어 전체 장비 적격성의 독립 확정은 `BLOCKED`로 남겼다. T6에서 별도로 주어진 유효성 확인서를 T8에 빌려 쓰지 않았다. 다른 중간 감사자 한 명이 허용 목록 밖의 시험 관리 경로를 열었다고 보고했으므로 그 감사의 PASS를 독립 합격 근거로 삼지 않았다.
- 같은 짧은 D-51 기록을 읽어도 일부 초안은 ‘다른 조건 충족’이라는 계획의 진술과 그 조건에 대한 독립 검증을 함께 미확인으로 표현했다. 짧은 추천에도 선택 지침을 연결하고, 원기록의 상태와 관측이 입증하는 범위를 각 출처와 함께 반환하도록 보완했다. 실제 최초 응답, 재시험, 감사 지적 후 기록 보정의 범위는 `review/ready-closure.md`에 구분했다. 자연어 지시가 모든 후속 답변에서 같은 판정을 보장한다고 해석할 수 없다.
- 검증 범위는 00–06의 소스 변경과 합성 행동 사례다. 이 비교에서 외부 서비스보다 우수하다는 결론이나 새 설치본의 동작을 도출하지 않는다.

## 재현과 검증

- 별도 이력이 없는 Codex 개발 에이전트에 고정된 플러그인 스냅샷과 배정 자료를 전달했다. 동작 시험 실행 모델은 `gpt-6-luna` / max였다. 역할 템플릿을 읽는 것과 해당 파일에 지정된 모델을 실제 배포 환경에서 실행하는 것은 구분했다.
- 원문, 요청, 판정표와 이전 응답을 응답자에게 함께 주지 않았다. 판정자는 X/Y 표식을 사용해 자료와 답변을 대조했다. 작업자들이 같은 파일시스템을 사용하므로 기술적으로 이중맹검을 보장하는 환경은 아니다. 자동 선택은 제공된 목록에서 선택한 통제 사례다. 설치된 Codex·Claude 새 세션에서의 발견·성능·비용은 측정하지 않았다.
- 원자료 ZIP에는 `control/source-before.json`, `source-after.json`(control 안), 단계별 patch, 요청·근거, `records/`의 원응답·실행자 열람 내역, `control/sequence/`의 시점별 임시 프로젝트와 `review/`의 독립 검토가 있다. 중간판의 실패도 포함한다. 원본 7개 파일을 대조할 때에는 `final-source.patch`를 사용한다.
