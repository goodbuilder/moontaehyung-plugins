# RIS 스킬 수정 계획안

**대상** `moontaehyung:ris` · **기준 버전** 0.19.2 · **작성일** 2026-11-23 · **상태** 00–06 원본 반영 · 07 미실행

[00–06 변경 및 검증 기록](verification-ris-skill-00-06.md) · [합성 시험 원자료](verification-ris-skill-00-06.zip)

첫 변경은 Researcher에게 같은 자료로 **표 하나를 확인하는 요청**과 **가능한 대안을 넓게 탐색하는 요청**을 각각 주는 데서 시작한다. 현행 응답을 보존한 뒤 위임 범위와 근거 인계 지시를 바꾼다. 그다음 후보 비교, 다음 작업 선택, 근거 정정, 재개를 연결한다.

완료된 스킬은 사용자가 선택을 요청하면 **현재 권고, 대안의 보류 이유, 결정을 바꿀 관측, 지금 가능한 다음 행동**을 설명해야 한다. 사실 조회는 요청한 사실과 출처로 끝낼 수 있어야 한다. 이 문서의 연구 자료와 수치는 모두 행동 시험용 가상 자료다.

## 3. 파일별 편집 명세

### 00 · 판정표와 현재 행동을 먼저 고정

- 두 manifest, 실제 `skills/ris/` 소스, 관련 Codex·Claude 역할 템플릿, Coordinator 템플릿의 상대 경로와 SHA-256을 기록하고 수정 전 사본을 확보한다. 캐시와 바이트코드는 제외한다. 각 묶음 시작 때 해시가 바뀌었으면 사용자 편집을 읽고 새 기준에 맞춘다.
- 4절의 **요청·자료**와 **채점 근거**를 분리한다. 현행판에 먼저 같은 입력을 주고 원응답, 실제 열람 위치, 수행한 작업, 불필요한 사용자 개입, 시험 프로젝트의 파일 차이를 남긴다. 개발용 대표 사례와 최종 확인용 변형을 미리 구분한다.
- 완료 증거는 현행판의 원응답과 재현 가능한 조건이다. 과거 대화에서 앱과 스킬을 혼동한 일은 T1을 고른 이유다. 이를 현행 스킬을 실제 호출한 재현 결과로 간주하지 않는다.

### 01 · 진입점과 Researcher의 위임 범위를 일치시킨다

**교체 위치** `skills/ris/SKILL.md`의 `description`과 `Classify the request first`, `skills/ris/references/role-workflow.md`의 `Assignment and return`, `agents/researcher.toml`과 `agents/claude/researcher.md`의 `Required procedure`.

1. 기존 description 끝에 “Also use for explicit requests to diagnose or improve the RIS skill or its role instructions.”를 추가한다. 기존 모호성 규칙 바로 앞에는 스킬이 명시되면 `maintenance.md`에서 원본을 확인하고, 앱이 명시되면 지목한 앱을 대상으로 삼는다고 적는다.
2. Coordinator는 위임문에 **전체 대안 탐색** 또는 **범위가 정해진 근거 확인**과 반환할 질문을 짧게 쓴다. 예를 들어 “표 2가 대상 장비의 p95를 보고하는지만 확인”은 후자다. 상위 연구의 폭과 미탐색 영역은 Coordinator가 계속 관리한다.
3. 두 Researcher 템플릿의 “Required procedure (complete every step …)”부터 7번 끝까지를 다음 조건부 지시로 교체한다. “For a full exploration, apply the complete breadth discipline and return checklist in the RIS research-exploration reference. For a bounded evidence check, inspect the assigned question and return the finding, locator, applicability and any material gap.” 전체 탐색의 원문 조회, 조합표, 자원 행렬, 추가 대안·반증 탐색은 참조 문서의 기존 요건을 따른다.

**판정** T1·T2. 명시적 스킬·앱 요청이 각 대상에 도달하고, 표 한 개 조회에서는 전체 후보표를 요구하지 않으며, 넓은 연구에서는 기존 폭이 유지되어야 한다. 좁은 위임을 이유로 상위 연구의 미조사 부분을 완료 처리하면 Coordinator 인계를 다시 고친다.

### 02 · 결정에 쓰는 주장에 원자료와 적용 범위를 연결한다

**삽입 위치** `skills/ris/references/research-exploration.md`의 `Completion and recommendation checks` 아래에 `Evidence behind a recommendation` 절을 둔다. `skills/ris/SKILL.md`의 `Carry research through to a usable result`에서 선택을 요청받았을 때 이 절로 연결한다.

- 권고를 좌우하는 주장에 한해 **주장 → 읽은 원문 위치 → 원실험·데이터 → 직접 보고·재인용·자체 추론 → 적용 범위·반증·미확인 사항**을 전달한다. 기존 ID가 있으면 재사용하고, 짧은 답에는 문장으로 표현한다.
- 삽입 초안은 “Trace a decision-changing claim to the experiment, dataset, or observation behind the cited documents. State what each source actually reports and where it applies. If their dependence cannot be established, leave it unknown.”이다.
- 같은 DOI라는 이유로 한 논문의 독립 표본 둘을 합치거나, 다른 논문이라는 이유로 같은 표본을 재분석한 일을 독립 재현으로 세지 않는다. Q/R에는 기존대로 질의·열람 사실만 남기고 해석은 답변이나 허용된 finding에 둔다.

**판정** T3. 네 문서와 두 실험을 구별하고, 원자료 관계를 입증하는 구절을 제거하면 해당 독립성 판단은 미확인으로 돌아간다. helper의 열람 수는 네 문서를 읽은 사실을 계속 표현한다.

### 03 · 후보 비교를 서로 다른 예측으로 연결한다

**삽입 위치** `skills/ris/references/role-workflow.md`의 `Responsibilities and handoffs`. 기존 Engineer·Planner 역할 설명 아래에 다음 인계 예시를 넣는다. 현행 템플릿이 이 절을 읽고 실행하면 템플릿 추가 편집은 생략한다. 특정 역할에서 인계 누락이 재현될 때만 해당 `agents/<role>.toml`과 `agents/claude/<role>.md`에 동일한 참조 문장 한 줄을 추가한다.

| 전달 | 반환해야 할 내용 |
|---|---|
| Researcher → Engineer | 두 후보 모두 설명하는 관측, 서로 다른 전제, 이를 지지하거나 반박하는 원문 위치. 자료로 구별할 수 없는 부분도 포함한다. |
| Engineer → Planner | 두 안의 평가가 달라지는 관측, 유효한 측정과 무효 조건, 필요한 자원. 임계값은 사용자 요구나 근거에서 가져온다. |
| Planner → Coordinator | 결과별 다음 행동과 기존 결정·후보 ID. 결과가 어느 쪽이어도 선택이 같은 시험은 그 이유와 함께 순서를 뒤로 둔다. |

**판정** T4. 판별 자료가 없으면 우열 미결을 허용한다. 판별 가능한 시험을 제안할 때는 각각의 가능한 결과가 후보 판단을 어떻게 바꾸는지 설명한다. 모델의 토론·투표 횟수를 근거 강도로 환산하면 실패다.

### 04 · 허용된 다음 작업을 선택하고 실제 관찰과 구별한다

**삽입 위치** `skills/ris/references/research-exploration.md`의 `Run the next investigation before closing the branch`에서 Ready·Conditional·Blocked 분류 앞. `templates/ris-coordinator-AGENTS.md`의 `Coordination`에는 이 규칙을 참조하는 한 줄을 둔다.

- 작업마다 **어떤 결과가 어느 결정을 바꾸는지, 필요한 자원, 지금 실행 가능한지**를 확인한다. 결정을 똑같이 구별할 수 있는 작업 중에는 자원·대기가 작은 쪽을 먼저 수행한다. 비용 미확인은 미확인으로 남긴다.
- 사용자가 조사 수행을 요청했고 읽기 가능한 기존 로그가 결정을 가르면 그 로그를 열어 판정한다. 막힌 장비 시험은 재개 조건을 표시하고, 가능한 독립 조사는 계속한다. 실제 관찰, 계산, 시뮬레이션, 제안한 시험을 구분한다.
- Coordinator용 초안은 “Before assigning more work, say which possible observation would change the current decision. Take the available authorized check that can distinguish those outcomes, and report what it actually established.”이다.

**판정** T5. 대상 장비 로그를 실제로 읽는다. 로그에 p50만 있고 요구가 p95라면 미확인으로 처리한다. 장비가 없을 때 실험을 마쳤다고 응답하거나 같은 자료 조사만 반복하면 실패다.

### 05 · 근거 정정 후 어떤 결론을 다시 열지 규정한다

**삽입 위치** `skills/ris/references/research-exploration.md`의 `Recording events`와 `skills/ris/references/shared-outputs.md`의 `Handoff`.

1. **정정 전·후 근거 확인 → 그 근거를 사용한 주장과 후보 찾기 → 권고 갱신 → 여전히 유효한 판단과 다음 확인 표시** 순서를 예시로 넣는다. 새 자료가 기존 값의 정정인지 다른 조건의 관측인지 먼저 확인한다.
2. 기록이 허용되면 같은 결정 ID의 현재 권고와 `CONTEXT.md`를 갱신하고, 이전 권고와 당시 근거는 이력으로 보존한다. 사용자가 이미 선택했다면 새 에이전트 권고만으로 과거 선택을 취소하지 않고 재검토 이유를 기록한다. 대화로만 답하는 일은 대화 안에서 처리한다.
3. 기존 `--expected-hash`와 preimage를 적용한다. 사람이 중간 편집한 파일은 다시 읽고 해당 범위만 병합한다. 부분 갱신은 인계에 표시한다. 선택적 `.ris/state.json`은 작업 상태와 참조를 담는 현재 용도로 사용한다.

**판정** T6·T7. 같은 정정을 두 번 전달해도 결정 이력은 중복되지 않는다. 공유 자료에 의존한 두 주장은 모두 재검토되고 독립 표본의 결론은 유지된다. 새 세션에서 현재 권고와 이유를 복원한다.

### 06 · 사용자에게 보이는 답과 결정의 주체를 명확히 한다

**교체 위치** `skills/ris/references/role-workflow.md`의 첫 문장과 `Assignment and return`, `skills/ris/SKILL.md`의 `Carry research through to a usable result`.

- 첫 문장의 “The Coordinator owns user questions and decisions …”을 “The Coordinator routes decisions to the user and owns assignments, dependencies, integration and completion. The user confirms goals, constraints and final selections.”으로 교체한다.
- 선택 요청에는 **권고와 이유 / 보류·제외안과 이유 / 뒤집히는 조건 / 다음 행동**이 드러나게 한다. 네 개의 고정 제목을 요구하지 않는다. 단일 사실 조회는 원문 위치와 답으로 종료한다.
- 독립 Auditor에게는 원문과 조건, 결론을 바꿀 핵심 주장을 넘긴다. 감사자는 역추적한 근거와 확인하지 못한 범위를 반환한다. 별도 감사자가 없으면 자기 점검으로 표시하고 독립 감사 상태는 `NOT_RUN`이다.

**판정** T8. 추천, 사용자의 명시적 선택, 단일 수치 조회가 각각 다른 결과·기록 범위로 이어진다. 스킬이 스스로 사용자 선택이나 독립 감사 완료를 선언하면 실패다.

### 07 · 실제 클라이언트 반영과 복구

- 아래 구조 검사와 4절 행동 시험을 별도로 실행한다. 역할을 고쳤으면 Codex TOML의 공통 본문과 Claude 역할 Markdown의 대응 본문이 함께 바뀌었는지 검사한다.
- 구현 수용 뒤에만 당시 원본에서 두 manifest의 버전을 같은 다음 값으로 갱신한다. 배포 시 유지보수 절차를 따라 설치하고 Codex·Claude의 새 세션에서 각각 역할 로딩을 확인한다.
- Codex 역할은 개별 프로젝트나 사용자의 `.codex/agents/`에 복사된 이전 TOML일 수 있다. 실제 선택된 역할·경로를 비교하고 사용자 변경은 좁은 diff로 보존한다. Coordinator 템플릿도 기존 프로젝트 지침에 자동 전파된다고 가정하지 않는다.
- 회귀가 생기면 해당 묶음의 diff와 사본만 사용해 되돌리고 영향을 받는 사례를 재실행한다. 적용 당시의 불완전한 Git 추적 상태 때문에 저장소 전체 reset·checkout은 적절한 복구 수단이 아니다.

## 4. 행동 시험에 바로 사용할 사례

이 표는 계획 검토자와 평가자용이다. 실행 에이전트에게는 입력 열과 **그 시점까지 공개한 원자료**만 전달한다. 정정 이후의 숫자나 평가표를 미리 보여주면 정정·재개 시험으로 인정할 수 없다.

## 5. 시험 방법과 수용 기준

**구조 회귀.** 플러그인 원본에서 아래 명령을 사용한다. 계획 작성 시 기존 스킬 테스트는 **50 passed**였다. 이 결과는 helper와 패키지 구조의 기준이다. 현행판·수정판의 행동 차이는 별도로 측정한다.

```sh
/usr/bin/python3 skills/ris/scripts/ris.py --help
env PYTHONDONTWRITEBYTECODE=1 PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 /usr/bin/python3 -m pytest -q -p no:cacheprovider skills/ris/tests
```

**비교 환경.** 각 클라이언트 안에서 기존판과 수정판에 모델·설정·자료·도구·권한·작업 한도를 동일하게 맞춘다. 주 응답자와 위임 역할이 실제 읽은 정의를 확인한 뒤, 버전별 새 세션과 일회용 프로젝트를 사용한다. T1은 명시 호출과 자연어 자동 선택을 구분하고, T6만 단계별로 자료를 공개한다. 기존 사용자 프로젝트에 테스트 자료를 저장하지 않는다. 첫 묶음에서는 T1–T3 각 조건을 판본별 한 번 실행한다. 전체 통합 때에는 T1–T8을 실행하고, 자료 계보·부적합 지표·정정에 민감한 T3·T5·T6은 서로 다른 새 세션에서 한 번 더 반복한다. 이는 회귀 탐지용 설계 횟수이며 통계적 우위의 표본 크기는 아니다.

**채점.** 출력에서 판본 이름을 가리고 순서를 섞어 별도 평가자가 원문과 대조한다. 실행자는 자기 과제와 자료에만 접근하게 하고 정답과 상대 응답은 평가자에게만 제공한다. 이 분리를 보장할 수 없으면 비맹검으로 표시한다. 두 클라이언트의 결과를 따로 기록하고 실행하지 못한 조건은 미실행으로 둔다. 키워드나 제목 일치만으로 정답 처리하지 않는다.

| 기록 항목 | 산출 방식 |
|---|---|
| 핵심 행동 | 버전·클라이언트·사례별로 통과한 변형 수 / 실행한 변형 수. 실패 이유와 판정을 가른 원문 위치를 함께 남긴다. |
| 판단 오류 | 독립 근거 과대계상, 필수 조건 오판, 충분한 근거가 있는 안의 불필요한 보류, 정정 누락, 비영향 결론의 불필요한 철회를 구분한다. |
| 사용자 부담 | T1·T2의 불필요한 재질문, T5의 불필요한 작업, T6 재개 때 사용자가 다시 설명해야 한 사항의 횟수. 합산 점수로 오류를 상쇄하지 않는다. |
| 권한·기록 | 무단 선택·파일 쓰기·허위 감사 완료 유무, T8 작업 전후 프로젝트 파일 차이를 확인한다. |

**전환 조건.** 필수 조건 오판, 근거 조작, 사용자 선택·기록 권한 침범, 정정된 근거로 유지한 권고는 이 고정 사례에서 한 건이어도 해당 묶음을 보류한다. 반대로 T6의 정상 조건에서 근거가 충분한 B나 A를 항상 보류해도 실패다. 기존판의 핵심 실패가 수정판에서 해결되고 기존에 통과한 대조군이 유지될 때 해당 묶음을 반영한다. 양쪽이 이미 통과하면 불필요한 문구 추가를 생략한다. 판정이 엇갈리면 누락된 원문·조건을 밝히고, 처음 보지 않은 표현이나 다른 분야 자료로 재시험한다. 합성 사례로 일반 성능 향상을 확정하지 않는다. 양쪽이 사례를 통과해도 지시가 문서상 충돌한다면 정합성 수정으로 분류하고 행동 개선 실적과 분리한다.

**경쟁 후보와의 연결.** T2·T3은 GPT Researcher식 문헌 탐색의 근거 품질, T4는 Co-Scientist식 가설 비교의 판별력, T5는 AI Scientist-v2식 실험 판단의 적용 범위, T6·T7은 Kosmos식 누적 지식의 정정·재사용을 시험한다. 위 시험의 비교 대상은 RIS 스킬의 이전·수정 판본이다. 네 외부 시스템의 우위까지 판단하려면 각 시스템이 지원하는 과제에서 입력·자원 차이를 기록한 별도 비교가 필요하다.

## 6. 첫 작업의 종료 지점

**00–02까지만 먼저 적용해 T1–T3의 현행·수정 응답을 비교한다.** 첫 결과물은 변경 전후 지시문 diff, 양쪽의 실제 응답, 읽은 자료와 결정 근거, 대조군 결과다. 이 단계에서 어느 지시가 효과가 있었는지 확인한 뒤 03의 인계 규칙을 넣는다.

기존 연구에는 Q/R 로그와 요약 4개 절의 호환성, 전체 Explore의 기록, 미초기화 프로젝트의 대화 전용 탐색 및 사용자 지정 기록 정책을 적용한다. 새 폴더·영구 상태·별도 서버를 도입할 필요가 드러나면, 어떤 행동 시험을 기존 구조로 충족할 수 없는지부터 기록한다.
